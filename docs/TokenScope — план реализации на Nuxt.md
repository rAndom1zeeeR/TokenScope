# TokenScope — план реализации на Nuxt

Обновлено 27 ноября 2026. Версия от 22 ноября описывала другой каркас (свой UI-кит, мок-API, `useFetch`, маршруты `/token` и `/wallet`). Ниже план, который совпадает с кодом.

## Как работать по плану

Проект делится на этапы, и каждый заканчивается тем, что можно открыть в браузере. Сейчас живыми данными закрыта карточка токена (имя, картинка, цена). История сделок, PnL, холдеры целиком и граф появятся только после базы и индексатора: публичный RPC это не отдаёт.

1. **Один этап — одна ветка.** Ветка `stage-3-token-card`, коммиты по Conventional Commits, в конце merge в `main`.
2. **Не идёте дальше, пока не выполнен критерий готовности.** Он проверяется руками: «открываю страницу, вижу вот это».
3. **Сначала документация, потом код.** В каждом незакрытом этапе есть блок «Что изучить».
4. **Один намеренный эксперимент на этап.** Сломайте что-нибудь (уберите ключ запроса, верните не тот статус, выключите кэш) и посмотрите, что произошло.

Сделанные этапы не переписываются. Если код и план разошлись, правится план.

## Архитектура

Один Nuxt 4 проект отдаёт и страницы, и API. Код интерфейса в `app/`, серверный в `server/`, контракт между ними в `shared/`. У каждой части свой TypeScript-проект, типы с сервера попадают в компоненты через `shared/types`.

Чтение состояния токена (минт, метаданные, картинка, цена) идёт напрямую в RPC и HTTP. Ответ собирается в одном обработчике, но каждый источник кэшируется отдельно через `defineCachedFunction`. Postgres и worker появятся только для истории, которую нельзя дёшево перечитать с цепи: свопы, переводы, позиции, граф.

### Зафиксированные решения

- **UI — Nuxt UI v4.** Кнопки, таблицы, аватар, тосты, скелетоны берутся из библиотеки (`UButton`, `UTable`, `UHeader`, `UPageHero`). Свой набор `UiButton` / `UiCard` не пишется. Тема: палитры `brand` (`#7cf5c0` на 400) и `ink` в `app/assets/css/main.css` через `@theme`, семантика (`primary`, `neutral`, `success`, `error`) в `app/app.config.ts`. В классах только семантические цвета (`text-muted`, `bg-elevated`, `border-default`), не сырая палитра Tailwind.
- **Состояние серверных данных — TanStack Query**, не Pinia и не `useFetch`. Плагин `app/plugins/vue-query.ts` создаёт `QueryClient` на запрос при SSR и на вкладку в браузере, после рендера кладёт `dehydrate` в `useState('vue-query')`, на клиенте делает `hydrate`. `staleTime` 30 с (столько же живёт кэш цены), `gcTime` 5 мин. Фильтры таблиц, когда появятся, живут в query-параметрах URL.
- **Composable ходит в свой API через `useRequestFetch`.** На сервере без сокета все посетители попали бы в одну корзину лимита, поэтому `useTokenQuery` пробрасывает IP в `X-Forwarded-For`, если прокси его ещё не поставил. Любой новый запрос к лимитированному `/api` повторяет этот приём.
- **Ожидаемый отказ — это данные.** `TokenLookup` = `ok` | `not-found` | `not-mint`. 404 и `NOT_A_MINT` не бросаются из `queryFn`: иначе Query их ретраит и не кладёт в кэш. Настоящие сбои (сеть, 500) бросаются. 429 не ретраится, остальное — не больше двух раз. На SSR «не найден» и «не mint» получают HTTP 404 через `setResponseStatus`, чтобы поисковик не индексировал пустую карточку.
- **Поиск всегда открывает `/tokens/:address`.** Клиент проверяет только формат base58 (32–44 символа). Точный адрес и «это mint» решает сервер: `@solana/kit` `address()` и владелец аккаунта. Если это не mint, страница токена предлагает `/wallets/:address`.
- **Суммы в минимальных единицах — строка.** `supply` в `TokenResponse` это `string`, потому что `bigint` не сериализуется в JSON. В число перевод только на границе отображения, и только если нет `ScaledUiAmountConfig`.
- **Внешний URL из метаданных не качается через `$fetch`.** `fetchJsonSafe` пускает только `https` без логина в URL, заново проверяет редиректы, резолвит DNS в момент соединения и отсекает частные IP. Картинка клиенту отдаётся только как обычный `https`. `ipfs://` и `ar://` переписываются на шлюзы.
- **Кэш Nitro в памяти процесса, ошибки не кэшируются.** Функция должна бросать, а не возвращать `null` на сбое загрузки, иначе пустой результат застрянет на `maxAge`. Цена при ошибке Jupiter возвращает `null` осознанно: токен без котировки это нормальный ответ, не повод ронять карточку.
- **Лимит запросов тоже в памяти.** `enforceRateLimit` на `GET /api/tokens/:address`: 60 запросов в минуту на IP (`X-Forwarded-For` за Traefik/Dokploy). Несколько инстансов `web` потребуют общее хранилище. До этого момента один процесс.

Соответствие экранов маршрутам: главная → `pages/index.vue`; карточка токена → `pages/tokens/[address]/`; кошелёк → `pages/wallets/[address]/`. Вкладки токена (Traders, Holders, Transfers, Links) и кошелька (Overview, Trades, Transfers) ещё не заведены. Когда появятся, родительский `tokens/[address].vue` держит шапку и `UTabs`, дочерние страницы рисуются через `<NuxtPage />`. Повторный `useTokenQuery` во вкладке не делает второй запрос: ключ `['token', address]` уже в кэше.

## Карта данных токена

Один минт читается одинаково для SPL Token и Token-2022. Программы: `TokenkegQfeZyiNwAJbNbGKPFXCWuBvf9Ss623VQ5DA` и `TokenzQdBNbLqP5VEhdkAMS9jvjjnWx4LfMXrnHEJEn`. Чужой владелец принимается, только если байты выглядят как mint (82 байта или расширенный mint с типом аккаунта 1). Иначе 400 `NOT_A_MINT`.

| Данные                                       | Откуда                                                             | Кэш                 | В коде                                         |
| -------------------------------------------- | ------------------------------------------------------------------ | ------------------- | ---------------------------------------------- |
| `decimals`, `supply`                         | аккаунт минта                                                      | 1 ч, вместе с метой | в API, на странице не показаны                 |
| `mintAuthority`, `freezeAuthority`           | аккаунт минта                                                      | 1 ч                 | нет                                            |
| имя, символ, `uri`                           | расширение TokenMetadata, иначе Metaplex PDA, иначе короткий адрес | 1 ч                 | есть                                           |
| `image`                                      | JSON по `uri` (`image`)                                            | 1 ч, ключ — uri     | есть                                           |
| `price`, `change24h`                         | Jupiter Price `v3` (`usdPrice`, `priceChange24h`)                  | 30 с                | есть                                           |
| `description`, ссылки                        | тот же JSON                                                        | 1 ч                 | нет                                            |
| роялти, creators, collection                 | Metaplex, байты после заголовка                                    | 1 ч                 | декодер читает только name / symbol / uri      |
| опасные расширения Token-2022                | TLV минта                                                          | 1 ч                 | вручную читается только тип 19 (TokenMetadata) |
| цена в SOL, ликвидность кривой, `complete`   | PDA кривой pump.fun                                                | короткий            | нет                                            |
| объём, ликвидность, FDV                      | DexScreener (Jupiter Price этого не отдаёт)                        | ~30 с               | нет                                            |
| топ-20 холдеров                              | `getTokenLargestAccounts`                                          | ~1 мин              | нет                                            |
| полное число холдеров, лента сделок, возраст | индексатор                                                         | база                | нет                                            |

`null` у `mintAuthority` значит, что допечатка закрыта. `null` у `freezeAuthority` значит, что заморозить кошельки нельзя.

Расширения Token-2022 лежат в том же аккаунте. У новых pump.fun (`create_v2`) они уже там, отдельный RPC не нужен. На старом SPL-минте список пустой.

- `TokenMetadata.updateAuthority` — кто может менять имя и uri. У свежих pump часто `null`.
- `TransferFeeConfig` — комиссия перевода в bps и потолок. У pump обычно 0.
- `TransferHook` — на перевод висит внешняя программа.
- `PermanentDelegate` — адрес, который может жечь и переводить чужие токены.
- `MintCloseAuthority` — минт можно закрыть.
- `NonTransferable` — перевод запрещён.
- `Pausable` — переводы можно остановить.
- `ScaledUiAmountConfig` — отображаемое количество не равно `raw / 10^decimals`. Делить supply вслепую на таком минте нельзя.
- `InterestBearingConfig` — баланс растёт по ставке.
- `MetadataPointer` — куда смотреть метаданные, если их нет на самом минте.

Metaplex PDA: seeds `["metadata", program, mint]`, программа `metaqbxxUerdq28cj1RbAWkYQm3ybzjb6a8bt518x1s`. Заголовок уже декодируется. Дальше по байтам лежат `sellerFeeBasisPoints` (500 = 5%), `creators`, `isMutable`, `updateAuthority`, `tokenStandard`, `primarySaleHappened`, `collection`. У `create_v2` этого аккаунта нет, метаданные только в расширении.

JSON по `uri`, откуда берётся картинка. У pump обычно `{ name, symbol, description, image, showName, createdOn }`. У обычных токенов ещё `external_url`, `animation_url`, `attributes`, иногда twitter / telegram / website внутри `extensions` или `properties`. `description` у мем-коинов часто пустой.

Кривая pump, PDA `["bonding-curve", mint]` у программы `6EF8rrecthR5Dkzon8Nwu78hRvfCKubJ14M5uBEwF6P`. Пока монета не мигрировала:

- `virtualSolReserves`, `virtualTokenReserves` — из них цена в SOL
- `realSolReserves`, `realTokenReserves` — ликвидность на кривой
- `complete` — кривая закончилась, торгуется уже пул
- `creator`, в новых аккаунтах ещё `isMayhemMode` и cashback

Цена, пока `complete === false`: `(virtualSolReserves / 1e9) / (virtualTokenReserves / 10^decimals)`. После миграции кривая цену не держит, это пул PumpSwap или Raydium.

Рынок, которого в минте нет: объём, ликвидность, FDV. Цена в USD и 24h уже приходят из Jupiter (`$0.00041`, `+128.4%` на главной — из фикстуры таблицы, на странице токена — из API). Объём и ликвидность — отдельный запрос к DexScreener.

Холдеры: `getTokenLargestAccounts` даёт топ-20 и raw balance. Полное число холдеров публичный RPC не отдаёт. Возраст монеты (первая подпись минта через `getSignaturesForAddress`) на публичном RPC дорогой и режется лимитом, его считает индексатор.

## Этап 0. Скелет — сделано

Nuxt 4, pnpm, строгая проверка типов (`pnpm typecheck`), ESLint (`pnpm lint`), форматирование oxfmt (`pnpm fmt`). Модули: `@nuxt/ui`, `@nuxt/eslint`. Порт разработки 3013. Секреты только в `.env`, в репозитории `.env.example`. README описывает запуск и уже работающие маршруты.

Не ставились и не нужны, пока не появятся в конкретном этапе: Pinia, VueUse как модуль, свой CSS-файл токенов, Prettier, husky. `@solana/kit` и `@solana-program/token-2022` стоят, потому что карточка токена читает сеть.

## Этап 1. Каркас UI — сделано

Тёмная тема через `colorMode.preference: 'dark'` и палитры `brand` / `ink`. Layout: `UHeader` (логотип, поиск по адресу вне главной, пункты Tokens и Wallets, мобильное меню в `#body`), хлебные крошки, `UFooter`. Главная: `UPageHero` и таблица-фикстура на `UTable` (сортировка колонок, бейдж индекса Live / Indexing / Ready). Поиск валидирует адрес и делает `navigateTo('/tokens/' + address)`, на главной есть кнопки USDC, BONK, JUP.

`error.vue` рендерит `UError` внутри той же шапки. `app.vue` задаёт `lang="en"` и `title · TokenScope`.

Маршруты, которые открываются:

- `/` — главная
- `/tokens/:address` — карточка, если адрес проходит `isSolanaAddress` (`definePageMeta.validate`, иначе 404 без запроса)
- `/tokens`, `/wallets`, `/wallets/:address` — заглушки

Вкладок токена и кошелька нет. Страницы `/dev/ui` нет: компоненты Nuxt UI не каталогизируем.

Крошки: `useBreadcrumbLabel` пишет символ токена в `useState` по пути. На клиенте метка снимается при уходе со страницы, на сервере остаётся в payload. Битый `%`-escape в сегменте не роняет страницу (`safeDecode`).

## Этап 2. Живой токен — сделано

`GET /api/tokens/:address` возвращает `TokenResponse`: `address`, `name`, `symbol`, `image`, `decimals`, `supply`, `price`, `change24h`.

Обработчик: лимит → `address()` из `@solana/kit` → `getToken`. Внутри параллельно идут цепочка «мета + картинка» и цена.

- RPC один на процесс, пересоздаётся, если сменился `solanaRpcUrl` (`useSolanaRpc`). В кэшируемой функции Nitro нет `event`, поэтому URL берётся из глобального `runtimeConfig`.
- Минт и PDA метаданных забираются одним `fetchEncodedAccounts`.
- Имя: расширение TokenMetadata декодером, при незнакомом расширении — ручной TLV (тип 19), иначе Metaplex, иначе адрес `AbCd…wxyz` и символ `UNKNOWN`. Нулевые байты старого Metaplex снимает `cleanString`, обычный `trim` их не убирает.
- Повторы внешних вызовов — `withRetry`. У `$fetch` к Jupiter `retry: 0`, чтобы не удвоить попытки.
- Ключ Jupiter уходит заголовком `x-api-key` и только из `runtimeConfig`, не из `public`.

Клиент: `useTokenQuery`. Страница показывает скелетон, «Token not found», «This is not a token address» со ссылкой на кошелёк, «Too many requests» и общую ошибку с `refetch`. `useSeoMeta` ставит символ в заголовок и `noindex` на пустых исходах.

Форматирование цены: `formatUsd` (`$0.00041`, прочерк если цены нет) и `formatChange` (`▲ +12.3%` / `▼ -4.5%`) в `app/utils/format.ts`. Это отображение, в `shared/` ему делать нечего.

**Что этот этап заменил.** Мок-генератор, faker, zod-схемы и пачка `useFetch`-composable из старого плана не нужны. Контракт и так один (`shared/types`), а карточка уже на mainnet. Пустая база не блокирует шапку.

## Этап 3. Карточка токена целиком

**Цель.** Шапка и блок фактов показывают всё, что можно прочитать без базы: полномочия, опасные расширения, текст и ссылки, рынок, кривую pump, топ холдеров. Фронт по-прежнему знает только `useTokenQuery`.

**Что изучить.** Аккаунт минта SPL и TLV Token-2022 в `@solana-program/token-2022` (`unwrapOption`, `__kind` расширений). Borsh Metaplex после полей, которые уже читает `metaplexHeaderDecoder`. `getTokenLargestAccounts`. Ответ DexScreener по паре токена. Почему `defineCachedFunction` кэширует успешный возврат и не кэширует throw.

**Шаги.**

1. Расширьте `TokenResponse`, не ломая текущие поля. Новые куски — вложенные объекты, чтобы шапка не разъехалась на двадцать опциональных скаляров:

```ts
export interface TokenResponse {
	address: string
	name: string
	symbol: string
	image: string | null
	decimals: number
	supply: string
	price: number | null
	change24h: number | null
	mintAuthority: string | null
	freezeAuthority: string | null
	description: string | null
	links: { website: string | null; twitter: string | null; telegram: string | null }
	/** Расширения, которые меняют смысл перевода или supply. Пусто на старом SPL. */
	flags: Array<
		| 'transfer-fee'
		| 'transfer-hook'
		| 'permanent-delegate'
		| 'closeable'
		| 'non-transferable'
		| 'pausable'
		| 'scaled-ui-amount'
		| 'interest-bearing'
	>
	curve: {
		complete: boolean
		priceSol: number
		liquiditySol: number
		creator: string
	} | null
	market: {
		volume24h: number | null
		liquidityUsd: number | null
		fdv: number | null
	}
	holders: Array<{ address: string; amount: string }>
}
```

2. Полномочия берите из уже декодированного минта. В запасном разборе `readMintFallback` дочитайте те же поля по смещениям, иначе токены с незнакомым расширением останутся без них.
3. Флаги собирайте из `__kind` расширений. Для пути fallback разберите TLV, который сейчас бросает всё, кроме типа 19. В интерфейсе флаг — это бейдж с коротким смыслом («перевод с комиссией», «supply на экране врёт»), не сырое имя расширения.
4. Если среди флагов есть `scaled-ui-amount`, supply на странице не делите на `10^decimals`. Покажите raw и подпись, почему. Остальным supply показывайте уже человеческим числом.
5. Metaplex: продолжите декодер после `uri` и заберите роялти и creators. Нет аккаунта — это `create_v2`, не ошибка.
6. JSON по `uri` уже качается ради `image`. Из того же объекта возьмите `description` и ссылки. Наружу пропускайте только `https`, тем же правилом, что `toPublicImageUrl`. Описание режьте по длине.
7. Кривая pump — отдельная кэшируемая функция. Нет аккаунта → `curve: null` (токен не с pump или уже не на этой программе). `complete: true` не используйте для цены: подпись «мигрировал», цену в USD по-прежнему даёт Jupiter.
8. Рынок — DexScreener, свой `defineCachedFunction` с коротким `maxAge`. Ошибка источника даёт `null` в полях рынка, карточка остаётся. Цена и 24h остаются на Jupiter, не заменяйте их вторым источником в том же поле.
9. Топ-20: `getTokenLargestAccounts`, `amount` строкой в минимальных единицах. Долю считайте на клиенте от `supply`, кроме `scaled-ui-amount`. Это не полное число холдеров и так и подпишите.
10. Соберите это в `getToken` так же, как сейчас цену и мету: независимые куски параллельно, у каждого свой кэш. Картинка и описание делят один разбор JSON, не качайте `uri` дважды.
11. На странице разнесите шапку и факты. `TokensHeader` остаётся именем и ценой. Факты, флаги, ссылки, кривая и холдеры — отдельные компоненты в `app/components/tokens/`. Скелетон на время `isPending` повторяет форму блока.

**Критерий готовности.** USDC, BONK и свежий pump-минт открываются. У USDC видны закрытый mint authority и отсутствие расширений. У pump до миграции есть цена в SOL и ликвидность кривой. У мигрировавшего `complete` не подменяет USD-цену. Токен с `ScaledUiAmount` не показывает выдуманный supply. Повторное открытие того же адреса в течение `staleTime` не создаёт второй волны RPC (видно в логах или по сетевой вкладке).

**Типичные ошибки.**

- Складывать холдеров, кривую и цену в один `maxAge`. Цена протухает за полминуты, метаданные — нет. Кэш на функцию, не на весь `getToken`.
- Возвращать пустой объект при ошибке DexScreener из функции, которую кэшируете на час.
- Считать топ-20 полным списком холдеров.
- Делить supply при `ScaledUiAmountConfig`.

## Этап 5. Postgres

**Цель.** Появляется база для истории. Карточка токена из этапа 3 не переезжает в таблицы: минт по-прежнему читается с цепи. Фронт карточки не меняется.

**Что изучить.** Drizzle (схема как TypeScript, `drizzle-kit generate` / `migrate`). Почему время в `timestamptz`, деньги в `numeric`, суммы токена в минимальных единицах. Индекс под конкретный `WHERE`, а не «на все колонки».

**Шаги.**

1. Postgres в `docker-compose.yml`, `DATABASE_URL` в `.env` и `runtimeConfig` (серверный ключ, не `public`).
2. Таблицы в `server/db/schema.ts`:

```ts
export const swaps = pgTable(
	'swaps',
	{
		signature: text('signature').primaryKey(),
		token: text('token').notNull(),
		wallet: text('wallet').notNull(),
		side: text('side', { enum: ['buy', 'sell'] }).notNull(),
		amountToken: numeric('amount_token').notNull(),
		amountUsd: numeric('amount_usd').notNull(),
		ts: timestamp('ts', { withTimezone: true }).notNull(),
	},
	(t) => [index('swaps_token_ts').on(t.token, t.ts), index('swaps_wallet_ts').on(t.wallet, t.ts)],
)
```

3. Рядом: `transfers` (подпись, токен, from, to, amount, ts), `trader_positions` (токен, кошелёк, объём, реализованный и нереализованный PnL, баланс — материализованный итог), `pnl_points`, `indexer_cursor` (токен → последняя подпись). Отдельная `watched_tokens` (адрес, первый просмотр, последний просмотр): её пишет `web`, когда карточку успешно открыли. Из неё потом оживёт таблица на главной.
4. Миграции в git. Ручных правок базы нет.
5. Клиент БД — один пул на процесс, по образцу `useSolanaRpc`.

**Критерий готовности.** `docker compose up` поднимает Postgres, миграции применяются на чистой базе второй раз без ошибки. Карточка токена работает при выключенной базе: RPC от неё не зависит.

**Типичные ошибки.**

- Тащить имя, картинку и цену в Postgres. Они уже кэшируются с цепи и разъедутся с реальностью.
- `float` для денег и `number` для суммы токена.
- Индексы «на всякий случай». Каждый индекс замедляет запись индексатора.

**Вопросы самопроверки.** Какой индекс покрывает «сделки кошелька по токену за период»? Почему карточке токена база не нужна?

## Этап 6. Индексатор

**Цель.** Свопы и переводы выбранного токена попадают в таблицы. Процесс `worker` переживает рестарт и продолжает с курсора. Повторный прогон не плодит строки.

**Что изучить.** Enhanced Transactions Helius (или разбор `getTransaction`: pre/post token balances). Идемпотентность `INSERT ... ON CONFLICT DO NOTHING`. Nitro tasks и `scheduledTasks`. Как по балансам отличить покупку от продажи и зачем делить сумму на `10^decimals`.

**Шаги.**

1. Ключ Helius только в `.env` / `runtimeConfig`. В git — имя переменной в `.env.example`. RPC карточки (`NUXT_SOLANA_RPC_URL`) и RPC индексатора разведите: лимиты у них разные.
2. Разберите одну реальную транзакцию свопа в обозревателе и в ответе клиента. Направление и сумма должны сходиться до кода парсера.
3. `parseSwap(tx): Swap | null` и `parseTransfer(tx)` — чистые функции в `server/utils` (или `server/services`, если файл разбухнет). Без сети, с фикстурами настоящих транзакций. Непонятное пропускайте с логом.
4. Задача `server/tasks/indexer/sync.ts`: курсор → страница транзакций → разбор → upsert → сдвиг курсора. Расписание раз в минуту, и только если `NUXT_ROLE=worker`. В `web` задача не тикает. Ручной прогон: `runTask('indexer:sync')`.
5. Сначала один небольшой токен за несколько дней. Сверьте число свопов с обозревателем.
6. Возраст токена (первая подпись минта) пишите в `watched_tokens` здесь, не в обработчике карточки.

**Критерий готовности.** Демо-токен индексируется до текущего слота. Второй запуск не меняет число строк. Убитый процесс продолжает с `indexer_cursor`.

**Типичные ошибки.**

- Запускать расписание в каждом `web`.

## Этап 12. Деплой

**Цель.** Демо по ссылке, репозиторий поднимается по README.

**Шаги.**

1. Один образ из `nuxt build` (`.output/`). В compose два сервиса с разным `NUXT_ROLE` и Postgres. Миграции на старте `worker`.
2. Dokploy: секреты в окружении, HTTPS, автодеплой с `main`. Закрепите 2–3 токена в индексаторе, чтобы первый визит не попадал на пустые вкладки. Карточка и без этого живая.
3. `/api/health` (процесс и доступность базы). Лимит частоты уже есть, проверьте его за прокси по `X-Forwarded-For`. Логи worker без ключей.
4. README: зачем проект, скриншоты, схема «цепь → кэш Nitro → страница» и отдельно «worker → Postgres → API», три команды запуска, метод PnL, что полное число холдеров и возраст считает только индексатор, план EVM.
5. Тег `v0.1.0`, лицензия MIT.

**Критерий готовности.** Чужой человек поднимает проект по README. На телефоне карточка токена и вкладки читаются. В истории git нет ключей.

**Типичные ошибки.**

- Индексатор внутри `web`.
- Демо, где все вкладки пустые, хотя карточка красивая. Рекрутёр не откроет второй токен.

**Вопросы самопроверки.** Что продолжит работать, если Postgres не поднялся? Что сломается?
